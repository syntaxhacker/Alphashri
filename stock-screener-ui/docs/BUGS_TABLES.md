# Table sorting & column-wiring defects

Read-only audit of every `TableColumnDef` / `initialState={{ sorting }}` surface in `src/`.
Each row below was traced in the source (column ids cross-checked against the `columns` arrays,
seeds against those ids, and sort behaviour against the shared table's comparator).

Two table implementations exist and behave differently:

| Component | Sort gate | Seed honoured? |
| --- | --- | --- |
| `src/components/common/TanStackTable.tsx` | `props.enableSorting ?? true` (line 128) | yes |
| `src/components/paper-trading/TanStackTable.tsx` (vendored; used by **all** of paper-trading, replay, backtest) | `props.enableSorting` (**no default**, line 123) | **no, unless the caller passes `enableSorting`** |

## Verified clean

These were cross-checked id-by-id and are correct — stated explicitly so the next audit can skip them.

- **Bot tables** (`bots/BotsPage.tsx`, `bots/BotHelpers.tsx`, `bots/StrategyPerformance.tsx`): every `initialState` seed matches a real column id; non-data columns (`status`, `strategies`, `actions`, `sl_tp`, `exit_reason`) are correctly `enableSorting: false`.
- **Events table** (`events/eventsColumns.tsx` + `EventsTable.tsx`): ids match accessors; `actions` disabled. No seed sort is declared, so nothing can silently no-op.
- **Experiments** (`ExperimentsResultsTable.tsx`): seed `profit_factor` exists, `enableSorting` is passed, `enableSortingRemoval={false}` matches the three-click contract.
- **Sector rotation** (`RotationMatrix.tsx:69`, `RotationBoard.tsx:162`): seeds `1M` / `period` exist in the column set; `RotationBoard`'s `<Show … keyed>` genuinely remounts (keyed `Show`, not a `key` prop) so the per-period seed re-applies.
- **Profitability / follow-through / breakouts seeds** (`Profitability.tsx:293,306`, `ReportFollowThrough.tsx:142`, `ReportBreakoutTable.tsx:274`): all four ids (`net_pnl`, `net`, `ret_pct`, `pct_above`) are declared columns.
- **Market screener** (`MarketScreenerPanel.tsx:80`): seed `market_cap_cr` exists and is consistent with `filterMarketRows(…, filters().sort)`; the rail's `market-filter-sort` values are the same `MarketSortKey` union — no drift. (Only the row-windowing defect applies.)
- **Value table** columns other than `name` (`value/valueColumns.tsx:113-282`): ids `==` accessor semantics, alignment correct, `flags` correctly disabled.
- **Pattern list / matrix seeds** (`PatternListView.tsx:228-280`, `PatternSymbolMatrix.tsx:255-330`): all seeded ids (`confidence`, `range_pos`, `bars_ago`) and the matrix's `score`/`pos` accessorFns resolve to real columns; row test ids are composite (`symbol-pattern-id-id`).
- **Deep-value / events / options-reading row keys**: unique (composite or `event.id` / `row.id`).
- **`sortByField` / `sortResults` / `tradeHistoryUtils.groupTradesByDate`**: null-safe guards present; no `null`-comparator NaN ordering found (unlike the shared table's `getValue` path, which coerces `undefined` to `0` — the mechanism behind the EventWatch finding, not a defect on its own).
