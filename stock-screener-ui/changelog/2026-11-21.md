## Fixed

- **Sub-11px text in the merged panels** — `NiftyFuturesPanel.tsx` and `NiftyItmPeFlow.tsx` (both from #195) shipped `9px` badges and `10px` axis labels, violating the hard 11px floor. Raised to 11px; `reportFontFloorAll` now sees the whole report surface clean.
- **Chart replay clip covered by a test again** — `NiftyChartPanel` clips *every* source at the playhead when one is supplied (replay is orthogonal to the source), so LIVE no longer draws unplayed bars. The old test asserted the pre-fix behaviour (3 bars with a 09:16 playhead) and has been corrected to 2.
- **Stale Index Report tests reconciled with the promoted type scale (11/12/13/17/23) and the single index selector** — the toolbar's duplicate index `Select` was removed during the redesign; several specs still asserted 11/12/15/16 and both selectors. No production behaviour changed for these.
- **HOME desk seed test raced its own lazy chunk** — `HomePage.test.tsx`'s `(seed)` test awaited the market-heatmap panel and then asserted `options-chain-window` **synchronously**. Every desk panel is a `lazy()` chunk behind `PanelSkeleton`, so a settled heatmap says nothing about the options window; on a loaded runner (and whenever the file ran alongside its neighbours) the sibling import had not resolved. It passed in isolation only because the chunk was warm. It was the **single failing test out of 10,950** in the PR-to-`main` full unit job. Now awaited on its own (`findByTestId`), matching the file's own convention. Reproduced deterministically: racy form failed 3/3 with `src/pages/home/` run as a set, fixed form passed 3/3 under the same load.
- **Backtest chart never appeared after a run (real bug, found by the full E2E suite)** — `BacktestChartTabs` read `const sym = props.selectedSymbol` and `const currentChartData = sym ? … : null`, two **non-reactive snapshots taken at mount**. The store's `selectedChartSymbol` starts `null` and is only filled once results arrive, so `sym` stayed `null` forever: the chart area kept rendering `Select a symbol` while the tab strip above it — which reads the prop reactively — showed the symbol as selected and highlighted. Both are now accessors. This is why the unit tests missed it: they mount with a static `selectedSymbol`, so a snapshot read looks correct. Added a test that starts `null` and sets the selection after mount (proven RED on the old code, GREEN now); `tsc` moved 322 → **321** because the non-null assertion it needed is gone.
- **`Box` silently dropped every numeric `style` value (real bug, 12 E2E failures)** — Solid writes `style` straight to the DOM, so `style={{ width: 440, "min-width": 320 }}` reached the browser **unitless**, which is invalid CSS: Chromium discarded all of it. On the backtest page that meant the right rail had no `width`/`min-width`/`max-width` at all, grew to fill the viewport (1251px in a 1132px layout) and starved the chart to **0px wide**. The chart was rendering — seven canvases, correct bars — inside a zero-width box, so `toBeVisible()` could never pass and every chart/overlay/zoom test in `all-strategies-backtest.spec.ts` failed. `Box` now appends `px` to numeric length values while leaving unitless properties (`z-index`, `flex-grow`, `line-height`, `opacity`, custom properties) and the unitless-legal `0` alone. Fixed at the component so every caller is safe, not just this one.
- **Zoom/error-scenario E2E specs asserted interfaces that no longer exist** — the zoom control is a non-searchable `Select`, which renders a **native `<select>`**; there is no `role="listbox"` popup to open, so the spec now asserts the option set and a real `selectOption`. The error-scenario test clicked `[role="option"]`.first(), which is the "No symbols found" placeholder before the 300ms search debounce; it now reuses the shared `selectSymbolAndRun` + `mockSymbolSearch` helpers. `all-strategies-backtest.spec.ts` went **12 failed / 21 passed → 27 passed**.
- **URL-driven backtest config was never applied (real bug, 13 E2E failures)** — `useBacktestQueryParams` called `useStoreSnapshot(subscribe, getBacktestState)`, **discarded the reactive memo it returns**, and read `getBacktestState()` directly. A plain snapshot read inside `createEffect` creates no dependency, so the hydration effect ran once — while `variations` was still empty, its early-return guard — and never re-ran when they arrived. Every `?p=` payload was silently dropped: strategy unset, symbols left at the store defaults (`NETWEB`/`SBILIFE`), custom params ignored. Bound the memo; all 7 URL-param tests pass. Added `useBacktestQueryParams.test.ts` covering the encode/decode round-trip, short-key payloads and a corrupt payload.
- **`selectSymbolFromMultiselect` clicked the wrapper, not the input, and never opened the dropdown** — a wrapper click lands on padding, leaves `focus` on `<body>` (`aria-expanded` stays `false`), so the typed keys went nowhere and no option ever appeared. It now clicks the input and waits for the listbox. `backtest-features.spec.ts` went **22 failing → 33 passing**; with `all-strategies-backtest` and `backtest-url-params` the trio is **67/67**.
- **`toContainText` on an `<input>`** — `toContainText` reads `textContent`, which is always empty for an input; the selection lives in `.value`. Switched to `toHaveValue`.
- **`gotoPaperAndSelectFirstBot` waited on a popup that cannot exist** — `bot-select` is a non-searchable `Select` (native `<select>`), so there is no `role=option` listbox; the helper timed out on every paper-trading spec that used it. It now selects the first real option value. `all-strategies-multi-signal-types` **24 failing → 12 passing**, `all-strategies-paper-chart` 17 → passing.
- **Strategy filter / quick filter / bot status spec drift** — the strategy filter is a native `<select>` (use `selectOption`), the history quick filter is a `SegmentedControl` of `aria-pressed` buttons rather than a select, and the history window defaults to **Today** while the mocked trades are dated 2026-03-02, so nothing matched until "All" was chosen. The bots spec expected `"Running"` but the badge renders `RUNNING #12345` (the "PID intentionally not shown" comment was stale). Cross-spec trio now **55/55**.
- **`screener-interactions` tested a control deleted on 2026-11-14** — it clicked `screener-view-toggle` → "Map" and asserted `screener-heatmap-*`, none of which exist: `3a557d12` removed the screener's inline heatmap in favour of the HOME desk's `market.heatmap` panel (already covered by `home-desk.spec.ts`). The test now asserts the **absence** of that control, so a silent re-introduction is caught instead of the suite staying red on a deleted feature. Verified `/screener?view=vis` renders no map; the only `MarketMapView` mount is the desk panel.
- **The Replay page crashed on any trade click (real bug, 25 E2E failures)** — `ReplayPage` calls `replay.setHighlightedTrade(...)` from both the chart's `onTradeClick` and the trade-row handler, but `ReplayStateHandle` never exposed it. The store has always exported `setHighlightedTrade`; only the hook's return object omitted it, so `TypeError: replay.setHighlightedTrade is not a function` hit the page error boundary and blanked the whole Replay screen. Surfaced by the full suite because the PR-level smoke set never opens Replay. Exposed on the handle + interface; `all-strategies-replay-chart` **25 failing → 23 passing**, `tsc` 321 → **319**.
- **The correlation chart's empty/loading overlay swallowed clicks meant for the toolbar above it (real bug)** — `CorrelationChart` renders `pos="absolute" inset={0}` overlays for "Loading chart data…" and "No chart data available". Because the panel collapses to 36px when it has no data, that absolute overlay sat over the **correlation toolbar** and intercepted every pointer event, so the timeframe/period controls were unclickable and `correlation.spec.ts` timed out on click. Both overlays are now `pointer-events-none`. Verified pre-existing (fails identically at `5127a6be`, before the `Box` px change), so this was not a regression from that fix. `correlation` **6 failing → 5 passing**, `sector-correlation` 6 passing.

- **Three informational overlays were silently eating clicks across the correlation screens (real bug)** — `CorrelationChart` (loading + empty) and `CorrelationHeatmap` (loading + empty) each render a `position:absolute; inset:0` panel over their chart. Those panels answered `pointer-events: auto`, so wherever the chart collapsed (36px empty state, or a matrix with no data) the overlay sat over the toolbar above and swallowed every click.
