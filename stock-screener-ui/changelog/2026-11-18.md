# Changelog — 2026-11-18

## Added
- **In-minute tape retry** — a failed chain fetch (or an empty chain / rejected spot) is retried up to `NIFTY_TAPE_FETCH_ATTEMPTS` (3) with 2–3 s backoff *inside the same minute* before the minute is journalled as a gap. A second tick cannot overlap a running one (`in-flight` skip). Covers the opening 09:15 tick, where the chain is often not populated yet.
- **Tape backfill from the 10-second chain feed** — `backfill_tape_from_chain10s()` reconstructs a missing TODAY minute from `nifty_chain10s` (aggregates, per-strike chain, ATM premiums, computed max pain) and appends it with `backfilled: true`, `source: "chain10s"`. Idempotent, never overwrites a recorded minute, never touches the current minute, never writes a full report. Triggered automatically on the first tick after a hole.
- `t_fetch` / `t_write` on every tape row (build latency is now auditable) and `backfilled_minutes` on `GET /nifty/tape/status`.
- `spot_raw` + `spot_source: "tape_reconciled"` whenever the tape/snapshot spot had to be corrected.
- `ce_oi_change_day` / `pe_oi_change_day` (OI − prev_oi vs the previous session's close) alongside new `ce_doi_interval` / `pe_doi_interval` (minute-over-minute), distinct from the existing vs-first `call_doi`/`put_doi`.
- **Breadth history** — `experiments/data/nifty_breadth/history/YYYY-MM-DD.jsonl`, one line per 60s refresh with the full breadth block + `t`, written from the existing refresh (no extra quote call). `last.json` keeps its `{at, block}` shape; history is never pruned. Kept warm by the report loop so a closed browser tab no longer loses the session (`NIFTY_BREADTH_HISTORY=0` to disable).
- `NIFTY_SPOT_SOURCE=ws|v3|v2` (default **`v3`**) for the 1s Nifty spot poll; `ws` prefers the pooled `nifty_md` `ltpc` feed and falls back to REST when that socket is not live.

- **IRFC 90 CE** trade page (`trade.html`) and full research page (`research.html`) — 09 Nov entry/exit, futures/basis/OI, option chain, 3D path, current mark-to-market, expiry scenarios.
- Dedicated **`reports/index.html`** — 58 cards / 5 groups / 145 report pages, generated by `scripts/market/reports_index.py`; `--check` validates every link.
- NIFTY 0-DTE 2026-11-17 research page — pin/gamma, participant flow, vol/decay, futures/cross-market, intraday anatomy, quant verdict/evidence.

- **Market Vis — nested sector treemap** — a second visualization (`Sector treemap`) beside the flat `Heatmap`, reachable from a new Vis selector. Sector blocks are summed from their stocks' sizes; each stock tile is sized by the selected "Size by" metric (descending) and coloured green/red by day change. Tail names per sector roll into one `Other (n)` child (top 12 per sector, `MAX_STOCKS_PER_SECTOR`), and null sectors go to `Unclassified`. Click a stock tile for the symbol dock; Expand opens a fullscreen overlay (Esc / × closes). Implemented as a wrapper over the unchanged shared stock-treemap builder, so the NSE and sector heatmaps are byte-identical.

## Changed
- **Tape row `t` is the FETCH START** (not the time after a ~50 s build), so a slow tick no longer lands its row in the next minute bucket. `t` keeps its meaning for consumers; `t_fetch` mirrors it and `t_write` records the write.
- **Snapshots adopt the reconciled tape spot** — `_build_snapshot_dict` (20s snapshot task + manual snapshot) cross-checks the chain print against the tape and keeps the raw value as `spot_raw`. The replay frame written by the recorder uses the same reconciled envelope.
- `buy_qty` / `sell_qty` / `last_trade_price` / `last_trade_qty` are `null` when Upstox never sent them (were `0`, which read as real "no buying / no trade"). Keys unchanged for existing consumers.
- `GET /nifty/tape` serves backfilled minutes when present; its docstring no longer claims past minutes are never backfilled.
- **Nifty spot REST path moved to V3** — `GET /v3/market-quote/ohlc` (verified in the bundled SDK and the existing batch path) instead of the deprecated `/v2/market-quote/ohlc`, with automatic V2 fallback (401 is not retried: the token is process-wide). Active source is logged once per change.
- Reports index is now mandatory whenever a report HTML is added, renamed or removed.
- 10-27 and 11-17 research pages state data-window and missing-lane limitations explicitly.
- Market tab label `Map` → `Vis`, with a `VIS_OPTIONS` + `VIS_RENDERERS` registry so adding a visualization is a registry entry, not a component rewrite. `?view=map` normalises to `vis` on read and is never serialised back; a saved `view:"map"` hydrates to `vis`.
- Heatmap tiles are now sized by the selected "Size by" metric (not market cap) and emitted largest-first; colour stays the green/red day-change ramp for every sizing option.
- "Size by" grew 5 → 12 metrics grouped Momentum / Trend / Performance / Size / Valuation. `@/ui` Select gained grouped options: `<optgroup>` in the native select, `role="presentation"` listbox headers, arrow keys skip headers, search prunes empty groups.
- Value rows in the embedded Market value view open the same right-side symbol dock as the market table when the row has an in-app chart; other rows keep `ValueDetailDrawer`. The standalone Deep Value tab is unchanged (no `onOpenSymbol`).
- `AGENTS.md §5`: visual checks are a hard gate for data-driven UI — screenshot every state of a changed control, read the PNG back, and add a range regression test when a visual bug escapes the suite.
- **Futures recorders now share one implementation** — `futures_common.py` owns parsing, complete-bar/backfill merge, basis arithmetic, contract cache, term snapshot and the recorder loop; NIFTY and SENSEX keep only a `RecorderSpec` plus their spot hook. `nifty_futures.py` 764 → 270 lines, `sensex_futures.py` 796 → 301; existing 34 tests plus 15 new spec tests pass with identical JSON rows/paths/status strings.
- **Generic (SENSEX / stock) recorder is now true NIFTY parity, from shared code**: `_tape_row.build_tape_row` is the single per-minute row builder (NIFTY's frozen field order; NIFTY output proven byte-identical by a golden test), so the generic row gains `t_fetch`, `t_write`, `call_wall`, `put_wall`, `ce_oi_change_day`, `pe_oi_change_day` and the conditional `spot_raw` (23 → 30 fields). Expiry selection uses `nifty.pick_nearest_expiry` (0-DTE only while `is_derivatives_open()`), cached per `(symbol, today, include_today)` so a session cache cannot keep today's contract after the close. The replay frame gains `mode` / `snapshot_at` / `source` and the reconciled spot (`spot_raw` / `spot_source`), matching the NIFTY line shape, so tape and replay agree. The tape/10s gap journals and the JSONL append / tail-read / atomic-write helpers are shared (`_journal.py`, `_jsonl.py`) with the dedupe policy passed explicitly — each journal keeps its previous rule (minute, minute+reason) and byte encoding. NIFTY-only `cas` / `spot_frozen`, the ±300 near-wall band and the chain window are untouched; the SENSEX 10-second window stays `max(750, 5% of spot)` (~42 strikes each side, was ±500). Net: `nifty.py` 4793 → 4646 lines, `options_recorder.py` 1403 → 1302, shared modules 299 lines.

## Fixed
- **`nifty_tape_report.py --json` wrote the default path regardless of the flag** — the CLI now writes both `--html` and `--json` to the requested paths.
- **Options parity test was still mocking the removed `get_option_chain` route** — `test_options_parity_fields` now feeds the raw `/option/chain` payload the recorder actually consumes, so the RELIANCE case no longer depends on live network data.
- **The 09:15 minute is no longer lost on one transient 502** — the tick retries within the minute instead of waiting 60 s (by which time the minute is gone).
- **Failed tape minutes were never retried or backfilled** — now retried in-minute and, if still missing, reconstructed from the 10-second chain feed and clearly marked.
- **Snapshot could disagree with the tape** — the recorder reconciled its spot but the snapshot/replay kept the raw chain print; both now use the reconciled value (`spot_raw` preserved).
- **Dead tape/report fields looked real** — absent Upstox order-book fields are now `null`, and day-change OI is no longer conflated with the interval delta.
- **13:05 “135M” flow artifact** — corrected to a 5-minute bucket of **132.0M**; busiest minute **38.7M at 13:09**, not a single 135M print.
- **Futures lead-lag clock bias** — naive 0.422 → **0.152** after aligning spot to the candle close; labelled as sampling, not a tradable lead.
- **Pin/gamma overclaims** — max pain moved 10×; pin unverified past 14:07 on 11-17; added null model and separate GEX definitions.
- **12:00 long-buildup framing** — mechanically confirmed (+50.5 pts / OI +96,915 / 350,220), explicitly not predictive (39.2% of 15m windows, p=0.679).
- **Selecting any non-default heatmap metric blanked the whole Market screener** with `Cannot read properties of undefined (reading 'trim')`. Cause: `norm()` (heatmapUtils.ts) log-normalises via `Math.log(Math.max(x, 1))`, so a metric whose whole range is < 1 collapses to 0/0 → NaN ramp index → undefined fill → `pickTextColor(undefined)` → `parseColor().trim()` throw. Market tiles now always route through the signed day-change ramp (floored extent, no log), the ramp's lerp has a guarded fallback, and `parseColor`/`pickTextColor` are total (bad fills degrade to black). Found by a browser visual check — the 323 passing tests had all fed day-change-shaped inputs.
- **Saved Market filters silently overwritten with defaults** when a saved table sort existed: the table-sort mirror patched `filters.sort` before `configReady()`, closing the saved-config latch so the real config GET never applied and a mount-default PUT won. The mirror is now gated behind `configReady()`.
- **Filter chip removal / Clear all did not refresh the results grid**: `patch()` notifies subscribers synchronously, so the patterns URL-sync subscriber re-entered with the previous filters and reverted the change before `loadResults()` read it. Filter actions now patch through `patchFilterAction()` with a `filterActionNotifying` guard that ignores re-entrant `applyFilters()`.
- **Config/options saves 422'd on the new `colorBy`**: the backend `MarketColorBy` Literal had 5 of the 12 metric values; widened to all 12, with `tests/api/test_user_configs.py` parsing the TS `MARKET_SIZE_METRIC_VALUES` declaration so the two layers cannot drift again.
- **Zero-value stocks dropped from the map / counter out of sync**: metric sizing floors a real zero to 1% of the smallest non-zero tile (null/NaN/Infinity still dropped), and the counter reads the builder's emitted tiles, not the filtered row list.
- **`/screener/config` blanked the whole page** — `TypeError: object is not iterable` out of `ScreenerConfigView`'s `filterArr` memo. The endpoint emits a screener's `filters` as a plain dict (`{f['key']: f.get('default') for f in filter_list}` in `get_screeners`), but the component iterated it with `for...of`; `ScreenerOption.filters` is typed `ProfileFilter[]`, so neither the compiler nor the tests caught it. `normalizeScreenerFilters()` now accepts an array of `{key, default, rangeDefault?}`, a `{key: value}` dict, or null/scalar: two-value pairs (`rsi_range: [30, 70]` or `rangeDefault`) split into `<key>_min`/`<key>_max`, and null values are skipped. A silently mis-built preview query would be worse than the crash — it would look like data.
- **Backend tests were unreliable under `pytest-xdist`** — failures moved between runs while serial runs passed. `snapshot._STALE_DIR` was one fixed repo path shared by every worker, and the autouse `clear_state` fixture `shutil.rmtree`-d it around every test, so workers deleted and contaminated each other's snapshots. A module-scoped autouse fixture now gives each worker its own directory (`tmp_path_factory.mktemp(f"market_screen_stale_{PYTEST_XDIST_WORKER}")`) and rebinds both the test module's and `snapshot`'s `_STALE_DIR`. No production code changed and no test was weakened.
