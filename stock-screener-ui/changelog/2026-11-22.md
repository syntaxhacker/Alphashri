# Changelog — 2026-11-22

## Added

- **Pure-Python backtest engine (`backtest/sim/`)** — replaces the Nautilus driver with ~890 lines that register the 14 `nautilus_trader.*` module paths the strategies import, so no strategy file changes. Fills stay at the signal bar's close and `ts_event` stays raw index nanoseconds (no timezone conversion), which is what `get_ist_time()` depends on. Verified trade-for-trade against nautilus_trader 1.231 on a frozen 90-bar ORB frame: entry 10:01 IST at 101.5, exit 10:05 at 102.8, gross 129.99999999999972, costs 10.85, TP exit — identical on both engines, with a negative control proving the comparison tolerance is not swallowing diffs. All four intraday/swing strategy suites return the same **311 passed** under both engines. Flagged off by default.
- **Parity harness** (`tests/test_backtest_shim_parity.py`) — runs both engines in separate subprocesses over the same pickled frame with the data source patched, then diffs every numeric field. Also asserts a non-empty trade list and an entry time inside 09:15–15:30 IST, so a silent clock shift cannot pass.
- **Engine-switch test** (`tests/test_backtest_engine_switch.py`) — unset/`nautilus` leaves the shim uninstalled, `sim` installs it and lists all 18 strategies, an unknown value fails with a named error.

- **Value filters on the Market table** — `peMax`, `psMax`, `pbMax`, `roeMin`,
  `divYieldMin`, `fcfYieldMin`, `debtToEquityMax`, `revYoyMin`, `epsYoyMin` in a
  collapsible "Value" band, plus a one-click deep-value preset
  (`P/E ≤ 15`, `ROE ≥ 15`, `FCF yield > 0`, `D/E ≤ 1.5`). Filtering is local on
  the cached frame — a test asserts no network request per filter change.
- **Value fields on the market row** — 10 more TradingView columns ride the same
  single scan (no second fetch, no second cache). `fcf_yield` is derived
  server-side. US universes inherit them automatically.

## Changed

- **`BACKTEST_ENGINE` selects the engine** at the top of `backtest/strategies/__init__.py`, before the lazy strategy imports resolve (the shim must be in `sys.modules` first). **`sim` is the default**; `nautilus` stays available as an opt-in A/B and fails loudly if the package is missing.
- **Frontend devDependencies** now declare `tslib` (`vite.config.ts`) and `@vitest/coverage-v8` (`vitest.config.ts`). Coverage is pinned to `4.1.0` to match the installed vitest; `4.1.12` declares a strict `vitest@4.1.12` peer. `knip.json` ignores `poc/**`, which is a POC and not shipped — all 7 unlisted-dependency findings are gone, `bun install --frozen-lockfile` still passes.

- **`global` market retired** from the value scan; only India and USA remain.

- **PR-gate doc corrected to match CI.** `AGENTS.md` told agents that a large/feature-bundle PR could "dispatch the full suite once", but `test.yml` has no `workflow_dispatch` trigger, so the 20-shard E2E is main/nightly only and that instruction could never be followed. The doc now states the real gate: smoke + the touched test files for a feature branch, with the full suite running on push to `main`, PR-to-`main`, and the 02:00 schedule. Adding the trigger was considered and deliberately rejected — the slowness is the reason the gate exists.

## Fixed

- **ORB backtest ignored the documented cooldown** — `run_single_stock_backtest` read only `cooldown_bars` (default 3), while `AGENTS.md` documents the ORB best config as `cooldown_minutes=75` and the live/research path reads minutes (`trading/autoresearch_strategies.py:171`). A backtest run with the documented params silently used a 3-bar cooldown. New `resolve_cooldown_bars()` precedence: explicit `cooldown_bars` (verbatim, including 0) → `cooldown_minutes` converted with `max(1, ceil(minutes / timeframe))` → legacy 3. Zero minutes means no cooldown; negatives raise `ValueError`. `ORBConfig` still receives only `cooldown_bars`, so the real engine's strict config is unaffected.
- **Dead branch in the shim's `_instrument_key()`** — both arms of the `isinstance` returned `str(value)`; collapsed, and the now-unused `InstrumentId` import removed.

- **Two latent breakages that the order-flow purge would have caused**, both
  caught before deleting anything: `api/broker_hub/adapters/upstox.py` imported the
  tick normaliser from `api/orderflow_stream.py`, and `api/fyers_options.py`
  imported `recorder_token` from `api/orderflow_recorder.py` inside a
  `try/except` that returns `None` — deleting it would have made every Fyers
  option-chain fetch silently empty. Both were relocated into `api/broker_hub/`
  and the Index Report chart verified green before any deletion.
- **A security control was nearly left unguarded** — `api/orderflow_logging.py`
  (credential redaction) is app-wide, not order-flow-only. Kept, renamed to
  `api/log_redaction.py`, and its guard test restored as `tests/test_log_redaction.py`.

- **Torch/CUDA + research deps from the root `requirements.txt`** — `torch`, `torchviz`, `captum`, `shap`, `wandb`, `python-binance`, plus the `nvidia-*`/`cuda-*`/`triton` wheels they pulled in. An import-reachability audit seeded from `api_server_fastapi.py` and `trading/runner_cli.py` found **zero** imports of any of them. ## Fixed

- **`start.sh` launched a recorder whose module no longer exists** — the Order Flow purge deleted `api/orderflow_recorder.py` but left `scripts/orderflow_recorder.py` and the `start_recorder()` supervisor in `start.sh`. Every `./start.sh` therefore started a script that exited immediately with `ModuleNotFoundError`, and the crash-loop guard retried it with backoff (60s → 900s) for the whole session. Removed the supervisor, its four call sites, `stop_recorder()`, the PID file, and the orphan-reaper; `scripts/orderflow_recorder.py` and `scripts/orderflow_probe_feed.py` deleted outright (both wholly dependent on deleted modules). Five salvageable scripts (`record_expiry_ticks`, `fetch_expiry_history`, `record_expiry_chain`, `build_entry_report`, `build_learning_report`) were **repointed** to `api.broker_hub` instead of deleted — they only needed `recorder_token` / `FyersAdapter`, which moved there.
- **The Deep Value preset returned 0 rows on India** — found by driving the live app, not by reading code. `fcfYieldMin: 0` was in the preset, but TradingView carries `free_cash_flow_ttm` for only **6% of Indian names** (measured directly against the scanner: 3 of 50). The filter was therefore narrowing on *missing data*, not on bad companies: preset went from 3,593 rows to **24**. Dropped `fcfYieldMin` from the preset (the filter remains available individually, where its coverage limitation is visible in context). Preset now returns **310**, and removing the P/E chip recovers to 789 — all verified in the browser.
- **The rail's Value band was undiscoverable** — it was a 10 px dim word wedged between MOMENTUM and TREND, with the one-click preset hidden inside the collapsed section, and the toolbar also had an unrelated control also labelled "Value". The band now has a `$` icon, an 11 px header reading **"Value filters"**, an active-count badge when collapsed, and the preset button **outside** the collapse (one click, not two). The toolbar view is relabelled **"Deep Value"** so the two surfaces can't be confused.

## Notes

- Diagnosed the 0-row preset by driving the live app with devtools: `peMax`/`roeMin` worked (905 / 863), `fcfYieldMin`/`debtToEquityMax` returned 0. The debt side was a **stale server** — the API had been running since Nov 20 while the code changed Nov 22, and `start.sh` runs without `--reload`, so it was serving pre-change code. `force=1` did not help, which is what made it look like a code bug.
